# Prism 应用设计尺度与页面配方

适用：Prism 第三方普通应用，2026-10-04。本文是设计建议，单位均为逻辑像素；主题
与 DSL 的硬契约见 [视觉参考](visual-design.md)，业务与包见 [开发指南](app-development.md)。
不要求开发者阅读旧 demo 源码来决定布局。下列数字不自动成为新的主题 token。

2026-10-05 修订：v21 不能作为已认可示范。先读
[视觉方案与密度验收](visual-approval.md)：内容决定行高，必要文字必须保留，
正常尺寸与紧凑尺寸都要视觉验收。以下尺度不授权把所有容器拉伸铺满。

## 1. 先确定信息优先级

设计前写清：用户此页要完成什么、唯一最重要的操作是什么、什么结果证明操作完成。
再把内容分为标题、主内容、主操作、次要操作、状态五类。一个窗口默认只保留一个
最强的强调色操作；多项同等操作用中性底色，通过选中标记区分当前项。

“图标为主”适用于导航和操作，不要求把文件名、文章、数值、错误原因替换成图标。
对用户不熟悉或后果较重的动作，使用图标加短标签，必要时使用文字按钮。当前没有
通用 tooltip 或无障碍名称 DSL，不能用“悬停后会解释”掩盖不可理解的纯图标。

| 区域 | 默认表达 | 避免 |
| --- | --- | --- |
| 应用头部 | 20–24 图标 + 一行页面标题 + 1–2 个动作 | 重复应用名、页面名、欢迎语三层大标题 |
| 一级操作 | 图标按钮，少量 accent | 所有图标都是鲜艳品牌色 |
| 分区 | 短文字子标题，可附一个图标 | 每条信息都包一层卡片和阴影 |
| 业务内容 | 有层级的正文、数值、真实缩略图 | 为追求图标化隐藏关键数据 |
| 状态 | 图标/选中条 + 简短结果 | 仅靠颜色，或动作刚发出就显示成功 |
| 提示/错误 | 说明原因 + 可执行的恢复动作 | 只有红色圆点，没有解释 |

普通应用不复制系统 Topbar、Dock、BSP 缝隙或窗口控制横线。系统横线有平台控制语义；
应用内 4px 短条只表达页面/选项选择，除非产品另有清楚的交互定义。

## 2. 字号与文本占位

默认四主题提供下列 token。引用 token，避免每个页面独立抄一套字号。

| 用途 | 默认字号 / token | 建议预留高度 | 使用原则 |
| --- | --- | --- | --- |
| 页面主标题 | 20 / `@font_heading` | 28–32 | 每页通常一个，紧凑页可以降为 title |
| 紧凑页标题、重要分区 | 18 / `@font_title` | 24–28 | 不与主标题同时抢同一区域 |
| 正文、设置项名称、列表主信息 | 14 / `@font_body` | 20–24 | 核心信息不降成 caption |
| 辅助说明、单位、更新时间 | 11 / `@font_caption` | 16–18 | 只用于次要信息，不能以淡色小字承载关键错误 |
| 关键业务读数 | 可选 24–32 数字字面量 | 32–40 | 局部强调；不是默认标题或现有新 token |

预留高度是布局盒建议，不是 `lineHeight` 属性。当前 Text 没有 fontWeight、字距、
自动省略号、多行换行或字体族属性。通过字号、颜色、间距形成层级，不叠放文本假装加粗。
`font` 是字号，不是字体文件。长名称在弹性区域中 clip，同时提供能够查看完整内容的
独立区域/页面；不要把裁掉关键信息当作设计完成。

示例中的英文用于匹配默认字体覆盖。中文产品要验证字体字形、实际 shaping 和输入法
能力；UTF-8 支持不等于中文字体 fallback、IME、自动换行已经完整可用。

## 3. 间距尺度与层级

优先保持同一页面中“相关内容近、不同分区远”。以下为推荐尺度，允许按密度调整。

| 关系 | 推荐值 | DSL 放置位置 |
| --- | --- | --- |
| 普通窗口内边距 | `@window_padding`，默认 14 | 根 Card.padding；不要再次加系统 outer_gap |
| 图标与相邻短标签 | 6–8 | HStack.spacing |
| 标题与辅助说明 | 4 | 两行所在 VStack.spacing |
| 同组按钮 | 8 | 操作 HStack.spacing |
| 普通卡片内部留白 | 8–12 | Card.padding |
| 同一分区的设置项 | 8 | 分区 VStack.spacing |
| 两个独立分区 | 12–16，宽裕页可用 20 | 页面 VStack.spacing 或显式分区容器 |
| 标题区与主内容 | 8–12 | 页面 Stack.spacing |
| 选中条与图标 | 6–8 | 保留指示槽，隐藏条而非槽 |

不要在根 padding、卡片 inset、内部 padding 三处重复加 14，导致内容被层层挤窄。
也不要所有层级都用同一个 spacing，失去分组区别。根 14 是当前主题设计值，局部
4/8/12/16 是推荐尺度；没有 `@spacing_md`、CSS margin 或 gap 对象这些隐式 API。

对齐优先级：同列文本起点一致 → 同行图标中心一致 → 操作区边缘一致 → 装饰微调。
数值后的单位使用 caption、间隔 4；相关数字可保留稳定宽度，减少更新导致的跳动。
不要在不支持的属性上写 `textAlign` 或 `tabular-nums`；通过容器和固定/弹性宽度安排。

## 4. 图标、按钮和选中标记

| 控件 | 可见图标 | 操作范围 | 推荐用途 |
| --- | --- | --- | --- |
| 紧凑工具栏按钮 | 18 | 32×32，padding 7 | BSP 常用操作，沿用主题 button_size |
| 常规强调按钮 | 20–24 | 40×40 或 44×44 | 空间允许时提高可点击性 |
| 主操作 | 24 左右 | `@primary_button_width`×`@primary_button_height`，默认 48×44 | 播放、开始、执行 |
| 只读状态图标 | 16–20 | 无 action | 状态辅助，不伪装为按钮 |
| 空状态图标 | 32–40 | 无 action | 与短说明、真正的操作按钮分开 |
| 选中指示 | 宽 16–24、高 `@indicator_height`=4 | 无额外 action | 不再重复放 “Theme/Selected” 标签 |

图标大小与点击范围分开。32×32 的 IconButton、padding 7 得到约 18×18 图标；
不是先画 32 图标再套 32 点击区。固定目标内的 hover/press 只动画 Visual，避免
点击区随缩放缩小。32px 是当前鼠标桌面建议，不能据此宣称已满足触屏或无障碍认证。

同一操作在不同页保持图标与位置一致。已有合法图标见视觉参考；找不到合适图标时，
先使用清楚的文字按钮或提出通用图标扩展，不依赖 emoji 或未知名称自动兜底。
危险操作不要紧贴主操作且使用同样的强强调样式；确认/撤销逻辑由应用实现。

## 5. 页面布局配方

### A. 设置页

```text
根 window，padding=主题值
├─ 头部 32–40：应用图标 / Settings / 可选搜索或刷新
├─ 页面导航 32–40（确有多个页面时）：图标 + 短标签或清楚的选中条
└─ 内容 flex=1
   ├─ Performance：CPU / Memory / GPU，同列标签、同列值
   └─ Appearance：材料图标、明暗选项；两类设置分别成组
```

一个设置项解决一个决定。名称在前，值或开关在后；帮助文字放名称下方，间隔 4。
单行项目建议 36–40 高，有辅助说明的项目建议 52–60 高。多个项目可以共用一张 Card，
用间距或细分割区分；不要为每项加入玻璃、投影和大标题。

不要让第三方应用默认带全局主题切换器。普通应用跟随主题；只有产品需要系统外观
管理时才调用 Host 的主题接口。应用自己的业务设置不要误标为桌面全局设置。

### B. 内容/工具页

```text
头部 32：图标 + 18px 标题 + 刷新
主体 flex=1：当前内容、数据或编辑器
操作区 36–44：主动作 + 少量次动作（确有需要才保留）
状态 16–18：保存结果/当前任务，避免重复主体文字
```

主内容优先得到剩余空间。不要为了看起来“高级”在小窗口中央保留巨大装饰徽标、
空白欢迎区或与功能无关的图片。留白应该区分信息；不应该挤掉业务内容或必要按钮。
状态区可选，若正文已说明状态就不必再加一行。

### C. 列表与详情

宽窗可以采用导航/列表/详情。DSL 已提供 min/maxViewportWidth/Height 条件显示；
参见[视口条件契约](../../../DSL_VIEWPORT_CONDITIONS.md)，不需要业务 viewport 回调。
跨宽度交付优先选择统一单栏 + 用户切页；实现双栏前确认最窄窗口仍可用。固定少量
条目可以显式声明，数量受控；不要把固定三行 demo 当作已有通用虚拟列表。
内容页滚动、任意动态列表仍需要相应通用接口，不能用 clip 冒充。

### D. 空、加载、失败和确认

沿用同一主体区域，保持头部和主按钮位置稳定。空状态采用 32–40 图标、14px 短句、
32–40 高的有效操作；加载不伪造进度；失败保留旧数据时必须明确哪些数据尚未刷新。
自定义确认层需要阻止底层操作、处理取消和焦点，不能只覆盖一张半透明 Card 就声称
是完整 modal。当前没有一条 DSL 声明自动完成通用对话框/焦点陷阱契约。

## 6. BSP 尺寸预算

以 244×420、482×204、482×420 为参考检查点，再加产品的正常尺寸。它们不是 WM
保证的最小尺寸。以最窄 244 为例：根两侧 14 后剩 216；横排两个 40 按钮及 8 间距
占 88，文本仍有 128。先算固定宽度总和，再分配 flex，避免最后一个按钮被裁掉。

以最矮 204 为例：根留白后高 176。头部 32 + 间距 8 + 底部 36 + 间距 8 后，主内容
仅剩 92。此时不能再堆 60 高欢迎区和多层分区标题；要简化内容或让用户切页。

压缩顺序：移除装饰 → 缩短次要说明 → 减少并排次要操作/切页 → 使用紧凑标题。
主要文字、核心动作和错误恢复最后保留。没有可用宽度 binding 时不要发明 `$viewportWidth`。
隐藏节点使用 visible；opacity=0 仍不是布局折叠或输入禁用。

## 7. 明暗、材质与对比

使用 `window/card/control` 和 text/mutedText/accent/onAccent；四材料×明暗都检查。
玻璃感来自下层背景、tint、边线和阴影共同作用，不靠叠多层白色蒙版。根外框与外阴影
归 WM，局部阴影从材料继承。square 下不强行把根圆角和玻璃写回来。

用实际背景检查文字及图标：明亮壁纸、深色壁纸、透明主题尤其容易暴露对比不足。
提高局部内容底色稳定性或选用合法材料，不随意增强整窗模糊。选中态同时有条/形状或
文字反馈；颜色不是唯一编码。当前没有可直接假设存在的 `@danger`、`@success` token，
需要这些语义时先约定主题契约，未约定前用现有 error/check 图标和明确文字。

## 8. 可复制的布局示例与交付

[compact-library.prism](../assets/examples/compact-library.prism) 是单根、无 binding 的
视觉组件，展示 32px 头部、14px 根留白、8px 分组、18px 标题、固定图标命中和命名反馈。
它不是完整应用：`library:refresh`、`library:open` 需要业务实现；三个条目是示意数据。
将其作为 Interface v2 的一个组件使用，或配合 [Counter 完整模板](../assets/starter/)
建立包。应用业务、Preview/Master 及状态接口不要从静态视觉示例推断。

交付设计时给出：区域/字号/间距表、binding/action 表、主题和 motion 依赖、最窄最矮
布局行为、空/失败状态和真实验证范围。自定义数值说明用途，无需把所有局部尺寸升级为
全局 token；需要跨应用共享的新语义才扩展平台契约。

### Box 内文字与指示线对齐

Card/Visual 的 fill 子节点默认占满可用宽度；只写父级 `align: "center"` 不会
把填充宽度内的文字居中。短标签与居中选中线对齐时用 `Text(..., anchor: "center")`，
右侧读数用 `Card(flex: 1) { Text($value, anchor: "right") }`。
不要拿纯色矩形中心代表文字中心；用真实字体截图核对。
