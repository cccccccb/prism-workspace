# 视觉方案与密度验收

2026-10-05：用户否定 v21 的视觉效果。v21 是功能与尺寸验证版本，不是认可的视觉基线。
用户已确认第二张 Concept B。其结构、密度与文字层级作为本轮实现基准；
参考[确认稿](../../../design/prism-concept-b/README.md)。

## 设计先于实现

用户要求探索或重新确定整体风格时，先用图像设计工具提供高保真效果稿，标注概念稿、
示例数据、正常与紧凑尺寸。让用户确认视觉方向后再修改生产 DSL、主题和运行会话。
图片生成不代表具备相同渲染、响应式或控件能力；选定后逐项映射现有契约，缺失的能力
另行设计通用接口。不要把效果稿直接塞进应用作为整页位图，也不把图中样例读数当作真实状态。

## 图标与文字共同构成界面

“图标为主”指熟悉的动作易扫描、视觉语言统一，不是减少所有文字。

- 页面必须有标题；分区必须有短名称；设置项必须有可理解的名称和值。
- 新页面导航、主题材质、采样频率等不熟悉的选项采用图标加短标签。
- 播放/暂停、前后曲、关闭等熟悉操作可纯图标；开关状态必须明确。
- 核心标签默认14px，不把所有名称降为11px辅助文字。允许内容充足而简洁。
- 同组图标统一尺寸、笔画和基线；常规图标18–20px，点击范围32–40px。
  图标默认中性色，强调色集中于主操作/当前状态；避免每个图标都有厚边框和彩色底牌。

## 留白必须有尺度

窗口增高不应让三条设置各自变成百余像素高的大卡片。普通设置行建议40–48高，
带辅助说明48–56；数字是起点，需按实际字体验证。内容行不使用 flex:1 均分剩余高度。

- 图标与标签6–8；同组行间0–8；独立分区12–16；标题与内容8–12。
- 根留白继续使用主题值。不要在根、外卡片、内卡片上重复叠大 padding。
- 剩余空间可留在内容末尾、交给正文/真正的内容视图，或由合理的内容最大宽度控制。
  不增加无意义信息来填满窗口，也不把按钮拉成通栏巨型块。
- 同时检验横向与纵向密度：防止“卡片内部空旷，边框之间又拥挤”。

## 材质和分组

共享内容区内优先使用对齐、短子标题和轻分隔线分组。一般保留窗口外壳与一层必要
内容底色；不要为 CPU/RAM/GPU 的每行再套强边框、玻璃、阴影。
背景可见度服务于内容对比。文字后方的纹理不应抢眼；不要靠多层白 tint 制造玻璃感。
外阴影、内阴影、边线各承担一个职责，不能全部高对比叠加。

## 评审门槛

1. 先看正常尺寸：是否像完整产品，有清晰的标签、内容密度和主次关系。
2. 再看窄窗和矮窗：主要任务仍可完成；次要项通过有名称的导航进入，不一律删除。
3. 比较同一页面两种尺寸，图标、字级、选中态和阅读顺序保持一致。
4. 检查明暗/壁纸对比、状态变化及错误恢复；布局不溢出只是功能门槛，不等于视觉合格。
5. 尺寸条件使用已有 min/maxViewportWidth/Height；滚动与虚拟列表仍需独立契约，不伪造属性。

效果稿只是候选方案；没有用户确认，不把某张生成图写成“最终批准的系统风格”。

## 从确认稿到实现不能自行降级

2026-10-05：Concept B 首版虽通过命中/尺寸测试，仍因视觉偏差被用户指出。后续必须
按[逐项对照](../../../design/prism-concept-b/FIDELITY_REVIEW.md)验收：

- 参考中的材质图片不能换成象征性图标；缩略图使用可编辑资产与 Image。
- 核心操作与次要操作的尺寸对比、进度轨道粗细/圆角、标签前后次序必须保留。
- 导航下划线、材质选中线、分段选择块承担不同视觉角色，不统一简化为短横线。
- 分区背景、细边框、内分割与大区分割逐个检查，不因“简约”自行省略。
- 图标按含义匹配，共用线宽；缺少图标时扩充通用图标集，不用任意已有图标占位。
- 正常尺寸建立比例，紧凑分支单独适配；不能让最窄窗口的按钮尺寸支配整个桌面。
- 同尺寸截图并排核对后才能描述完成度；通过测试不等于已获得用户视觉认可。
