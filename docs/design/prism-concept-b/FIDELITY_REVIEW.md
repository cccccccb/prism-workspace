# Concept B 对照修订

2026-10-05：用户指出首版实现与确认稿存在显著偏差。首版的功能通过记录不能当作
视觉验收；本轮按原始参考图逐项恢复比例、控件语义和层次。

## 对照清单

| 区域 | 首版偏差 | 修订目标 |
| --- | --- | --- |
| 页面结构 | 内边距小，分组间距混用 | 正常双窗内容起点向内对齐；标题、导航、内容分层 |
| 导航 | 任意替代图标、短状态线 | 对应的 monitor/brush/activity/layers/heart-outline；整段下划线 |
| 监控条 | 4px 太细，直角，数据列漂移 | 7px 圆角轨道；数据统一靠右，固定标签列 |
| Performance | 行底色过强或没有完整边界 | 共用一张低对比背景、细边框与两条内分隔线 |
| Appearance | 使用水滴等图标替代图片 | 四张独立材质纹理缩略图、名称、选中框与下划线 |
| Light/Dark | 两个分散按钮 | 带共同底框与选中块的分段选择器 |
| Monitoring | 缺背景及分组线，采样标签错位 | 与 Performance 同语言；开关圆角，采样分段选择器 |
| Music | 播放按钮过小、时间在进度条上方 | 正常44px主播放、36px次操作；时间在进度条下方 |
| Library | 无当前曲目底色、列表与主内容无分割 | 真正绑定当前曲目；完整分隔线、封面/作者/时长层级 |

## 尺寸与资产

以1280×720双窗的客户端620×540为主要比对尺寸。参考图1672×944缩放到相近尺度
后比较控件比例，不把每个像素直接照搬到另一种尺寸。低矮或窄窗口使用显式紧凑分支；
紧凑分支不能反过来限制正常界面的控件尺度。

材质缩略图是可编辑 SVG 设计资产，源文件在 `materials/`，生成的192×144 PNG进入
Preferences应用包，通过既有 Image 接口绘制。两种配色均有对应资源。缩略图用于识别
材质，不在客户端伪造跨窗口 backdrop，也不代表当前背景的实时截图。

共享图标追加在原枚举末尾，保留既有值。Host/SDK与使用新图标的应用需要一起发布。
没有在WM添加应用识别或绘制分支。

## 验收方式

真实GPU截图对照确认稿；分别检查正常双窗、明暗、矮窗。检查选中态由业务确认、
所有可见控件可命中、材质图片加载成功。尚未实现的曲目菜单不伪装为有效菜单：
列表保留播放入口，概念稿中的三点菜单属于明确的功能差异。

## 最终布局约束

- 正常标题24、分区标题18、正文14、辅助11；导航组最多416逻辑像素，不随宽窗无限拉开。
- Preferences总览分区显式预算146/107/105高，区间12；内容不足时用紧凑页，不平均拉伸分区。
- Music正常主播放44、次操作36；7px监控条与5px播放条均有圆角。紧凑播放条总高45，
  包括5px轨道、4px间距和36px操作区；错误信息出现时仍为曲库保留完整空间。
- 设置标题、内容分组与读数列对齐；主题样本64×48，选择框/下划线与主题确认状态绑定。

## 验证记录

本轮相关测试4项通过：应用模板、业务工作、布局、Skia损伤绘制。布局增加正常实机
620×540及断点600×540，四材质×明暗×八种尺寸；新增所有可见节点的分组边界检查，
弥补仅检查点击未发现分区相互挤压的问题。新图标全部纳入可见画布内的绘制/损伤验证。

真实V3D会话检查1280×720正常双窗、明暗，以及1024×600两/三/四窗和鼠标切页。
记录位于 `dist/validation/concept-b-fidelity/`；失败记录保留。一次并发启动遇到已有的
模块20ms入口预算超时，视觉probe改为错开启动后验证；本轮没有声称修复该启动预算问题。
视觉测试和资源导出工具不进入生产包。尚未重新打包或替换正在运行的VNC。
